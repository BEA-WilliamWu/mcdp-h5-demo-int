This revision adds PEECHJ7A to the existing Pe3Api/Pe3Client integration,
including the integration OpenAPI and 18 generated wire models.
The first returned contact is selected, as confirmed by the user.
ehj7aExtAdrLin1O..4O map directly to IPE debtor.postalAddress.addressLine1..4.
Outer padding is stripped and blank line positions are preserved.
Successful empty address results omit the address. Failed or malformed host
responses stop payment submission with the existing service error 600000.
Country/town mapping now follows the approved contact-type rules:
- H/C/I structured addresses use ehj7aCodCountryAdrO.
- Non-structured types 40/50/60/70/80/90/00/ZZ/Z0/Z1 use ehj7aCodCtryValO.
- Country codes are trimmed, uppercased and validated against Java ISO alpha-2
  countries. Invalid nonblank codes are logged/omitted; no alpha-3 conversion.
- H uses ehj7aDesDistrictO for townName; C/I use ehj7aOvrCtyDesO.
- Blank preferred town falls back to ehj7aDesCityO; outer padding is stripped.
- Unknown contact types omit country and may use generic city for townName.
- Country-only or town-only results retain an address object; all-empty mapped
  fields omit the object.
The fifth formatted line remains unmapped. Province/area fields are not appended.
The BCO address query and PartyPostalAddress DTO are removed. Apply the deletion
listed in DELETED_FILES.txt to the actual target codebase as well.

PEECHJ7A DEBUG entries identify the fields used for country and townName,
correlated by messageId. An omitted field is reported as none. In SIT, enable
logging.level.com.hkbea.hth.service.payment.ChatsPaymentService=DEBUG
to inspect the selected field names.

The supplied request form confirms collection PE9CHJ7A and Alnova account-key
lookup. PEECHJ7A shares the existing PEECHI11 client and HTH gateway.
In SIT, submit one CHATS payment and match its messageId to the INFO entry
PEECHJ7A enquiry completed with returnCode=00.
