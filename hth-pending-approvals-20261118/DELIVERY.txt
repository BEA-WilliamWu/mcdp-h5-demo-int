本次行为
- Pending Approvals、My Approval List、Activity Log（CREATED / ALL）、Audit Log
  在原查询结果补齐 userChannelType 后，由后端根据当前调用门户的 HTH toggle 过滤。
- 沿用请求上下文 isAdmin：true 为 BM，读取 ENABLE_HTH_BM_ONBOARDING；
  false 为 CM，读取 ENABLE_HTH_CM_ONBOARDING。缺少标记时沿用现有 CM 默认路径。
  标记由现有 UserTypeFilter / MACFilter 从请求 isAdmin 头设置，本次不修改门户识别逻辑。
- 不根据交易属于 CM/BM、操作人角色或目标用户渠道选择 toggle。
  同一列表中的 CM/BM 来源 HTH 交易均使用当前调用门户的开关。
- 通过原有 CustomConfigUtil adapter 读取当前值，去空白后 Y（忽略大小写）为开启。
  N、缺失或读取失败沿用现有关闭逻辑；每个结果集最多读取一次当前门户开关。
  不读取另一门户开关，不新增跨请求缓存。
- 开启：返回原列表记录；关闭：仅移除明确标记为 HTH 的行。
  UNKNOWN、BCO、无渠道字段、空字典、无关任务和已上线 Inquiry 保留。
- 沿用上一版渠道识别规则，不增加快照/用户表查询，不根据名称/URL/操作人猜测。
- 不修改计数接口、响应中的独立计数字段、原 SQL 查询范围、排序或 BM 查询条数上限。
  因此关闭开关后，实际返回条数可能少于标题计数；过滤后不补足原查询上限条数。
- 仅过滤返回的列表副本，保留其余行、顺序和字典字段，不删除历史或修改审批规则。

保留的渠道字段约定
交易：transactionDTOs[i].dictionaryArray[0].nameValuePairDTOArray
审计：auditList[i].dictionaryArray[0].nameValuePairDTOArray
条目 name / genericName 均为 userChannelType，datatype 为 java.lang.String。
后端读取第一份字典中名称匹配且 value 精确为 HTH 的标记后决定是否过滤。
返回给前端的其余记录仍保留该字段，不要求前端再实现本次开关过滤。

交易渠道识别（沿用上一版）
- MT_N_CUS / MT_N_UUS：读取已有或只读取得的提交快照，明确 HTH / BCO 则返回该值；
  没有可靠目标用户渠道时返回 UNKNOWN，不读取操作人渠道替代。
- UAT_N_HUA_NEW / EDT / DEL、PP_N_HTH_CERT_UPL、PP_N_HTH_ENB / EDT / DIS 标记 HTH。
- 其他任务维持原响应，不新增渠道字段。

UAT_N_HUA_NEW / UAT_N_HUA_EDT / UAT_N_HUA_DEL
