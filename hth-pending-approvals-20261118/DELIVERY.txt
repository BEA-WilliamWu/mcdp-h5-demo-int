transactions 接口（此前已交付，本次保持原样）
Pending Approvals:
GET /digx/v1/transactions?view=approval&discriminator=ADMIN_MAINTENANCE
My Approval List:
GET /digx/v1/transactions?view=approved&discriminator=ADMIN_MAINTENANCE
Activity Log（本人发起记录 / Viewer 查看记录）:
GET /digx/v1/transactions?view=created&discriminator=ADMIN_MAINTENANCE
GET /digx/v1/transactions?view=all&discriminator=ADMIN_MAINTENANCE
字段位置：transactionDTOs[i].dictionaryArray[0].nameValuePairDTOArray
- MT_N_CUS / MT_N_UUS：从已有或只读获取的提交快照中读取 userChannelType，
  明确的 HTH / BCO 分别返回 HTH / BCO，缺少可靠依据返回 UNKNOWN。
- UAT_N_HUA_NEW / EDT / DEL、PP_N_HTH_CERT_UPL、PP_N_HTH_ENB / EDT / DIS 返回 HTH。
- 其他交易任务保持原响应，不新增字段。不改变列表数量、排序及计数接口。

Audit Log 查询结果（本次新增）
GET /digx/v1/audit?userID=...&startTime=...&endTime=...&activity=...&partyId=...
字段位置：auditList[i].dictionaryArray[0].nameValuePairDTOArray
每条非空审计记录追加或替换一项：
{
  "name": "userChannelType",
  "genericName": "userChannelType",
  "value": "HTH",
  "datatype": "java.lang.String"
}
- 以下 15 个明确 HTH onboarding taskCode 返回 HTH，范围与现有审计下拉一致：
  MT_N_CUS_HTH / MT_N_UUS_HTH / MT_N_RUS_HTH
  UAT_N_HUA_NEW / UAT_N_HUA_EDT / UAT_N_HUA_DEL
  UAT_N_HAP_GEN / UAT_N_HAP_REGEN / UAT_N_HAP_RVL
  CM_N_HAP_SETUP / CM_N_HAP_RESET / PP_N_HTH_CERT_UPL
  PP_N_HTH_ENB / PP_N_HTH_EDT / PP_N_HTH_DIS
- 其他 taskCode（含空值）返回 UNKNOWN。这不是 API Password 状态。
  审计查询列表不带目标用户快照；不能把操作人渠道当作目标用户渠道，
  也不能仅凭旧共享 MT_N_CUS / MT_N_UUS / MT_N_RUS 判断 BCO 或 HTH。
  本次不额外查用户表或审计详情，不反推 BCO；旧记录不会被误隐藏。
- 已上线 Inquiry 不属于此次 HTH onboarding 标记范围，返回 UNKNOWN 并保留显示。
- 不按活动名称、通用 HTH 前缀或请求 URL 参数猜测渠道。
- 保留其他字典字段；重复调用不重复增加该字段；不改原列表行数、顺序、
  taskCode、Activity 文案、操作人、状态、引用编号或审计详情。
- 本次仅接入 postSearch 查询结果，未修改单条 audit read 或审计写入流程。

前端对接
- 查询结果补字段不依赖开关值，后端不新增 HTH 记录过滤。
- 前端沿用当前门户的 CM/BM HTH 开关；关闭时只隐藏 value === 'HTH' 的记录。
- UNKNOWN、BCO、缺少字段的旧版本响应均保留。
- 字段必须在 nameValuePairDTOArray 中按 genericName/name 找到后取 value，
  不假定它在数组中的固定下标。
- 原有两个 Audit Log 下拉的 HTH toggle 过滤逻辑维持原样。
- 前端过滤后的条数、分页由前端处理；原有后端计数/查询范围未改。
