接口与字段

在每条相关 transactionDTOs 记录的
  dictionaryArray[0].nameValuePairDTOArray
中追加或替换一项：
{
  "name": "userChannelType",
  "genericName": "userChannelType",
  "value": "HTH",
  "datatype": "java.lang.String"
}
现有字典内容保留；重复补充不会在第一项字典内生成重复字段。

渠道来源
1. MT_N_CUS / MT_N_UUS（User Management 创建/编辑）：
   优先读取交易响应已有的 UserExtensionDataDTO 快照；响应未附快照时，
   按交易编号只读已保存的提交快照，取其中 userChannelType。
   不查询实时用户表，也不会把完整提交快照补回列表响应。
   明确的 HTH / BCO 分别返回 HTH / BCO；空值、未知值、缺少快照或读取失败
   返回 UNKNOWN。该值只是渠道识别结果，与 API Password 状态无关。
2. HTH 专用任务直接返回 HTH：
   UAT_N_HUA_NEW / UAT_N_HUA_EDT / UAT_N_HUA_DEL
   PP_N_HTH_CERT_UPL
   PP_N_HTH_ENB / PP_N_HTH_EDT / PP_N_HTH_DIS
3. 其他任务保持原响应，不新增字段。不根据名称或 HTH 前缀猜测渠道。

前端对接
- 本次后端不读取 HTH 开关、不过滤记录。
- 前端沿用所在 CM/BM 的 HTH 开关；关闭时只过滤 value === 'HTH' 的记录。
- BCO、UNKNOWN、没有此字段的记录保留，避免误隐藏旧审批申请。
- transactions/count 及后端列表数量、排序、分页均未改。
  前端过滤后的展示数量、分页需由前端一起处理；不能直接当作后端已过滤。
- 同一 view=approval 接口的其他调用方也会得到该字段。
  view=created / approved / history 等其他视图未接入本次补充。

定位日志
只有快照读取失败时增加一条统一 BeaSystemOut 日志：

不打印快照、Code、密码或用户联系方式；读取失败不阻断审批列表。
