BCOH2H-1955 — Code 重设无需旧密码；HTH 保存状态，DSP 保存密码 Hash
2026-11-14（CM 配合最新 TL DSP e76cf79 的最小适配）

本次实现
1. CM 保持 Code + 新密码 + 确认密码的页面。Code 的审批、24 小时有效期、错误次数和一次性使用校验保留。
2. 浏览器直接将新密码 UTF-8 字节用 DSP 公钥加密，不先计算密码 Hash，也不先 Base64 编码密码。
   匹配 TL RsaCryptoCipher 的 SunJCE 参数：OAEP SHA-256、MGF1 SHA-1、空 label，密文使用 Base64。
   仅 HTH 页面新增 dsp-encrypt.js；复用 BCO 公共 RSA 大整数运算，不修改公共加密文件。
   CM 后端只处理 Code 信封及 DSP 密文，仍不取得密码明文。
3. 两个 DSP 接口路径不变：POST /password/v1/public-key、POST /password/v1/modification。
   取公钥仍传 hashValue = lowercase hex SHA-256(六位 randomNumber)。
   保存仍传 function、clientId、closeId、newEncryptedPassword、randomNumber。
   SETUP -> A：仅允许不存在有效密码时创建。RESET -> M：有有效密码时替换；完全没有该 clientId + closeId 记录时首次创建，无需旧密码。
   只有停用记录时拒绝；查询异常不作为不存在处理。不修改 TL 的 A 创建分支。
   oldEncryptedPassword 是兼容保留字段，已不参与本接口校验；没有新增 R、queryOnly 或状态查询 API。
4. DSP 保留 TL 实现：解密后 HashUtils.sha256(decrypted)，保存 64 位小写 hex SHA-256。
   DSP 源码 YAML 的 Base64(password) / MGF1 SHA-256 说明与该实现不一致，本次按实码对齐。
   本轮未更改 TL 的 API/DTO/YAML、公共 RSA、Hash、配置及 POM。
   修正 DSP_AUTH_CREDENTIAL 的 MyBatis mapper namespace；保存失败不得返回成功。
5. CM 密码接口沿用原 BM Client ID 校验的 DSPApiAdapterImplConfig：
   DSP.SERVICE_URL、DSP.APIC_CLIENT_ID、DSP.APIC_CLIENT_SECRET、DSP.CHANNEL（原默认 BCO）。
   DSPApiClientFactory 已恢复为 QTES2 同步版本原样；BM 校验页面和 HostToHostManagement 调用代码未改。
   H2H.* 继续用于原 Inquiry，密码接口不读取或回退到该配置。
   密码方法在 DspClient 中独立增加，共用原工厂、Header 和 SDK 底层传输，原 clientApi() 保持 SDK 实现。
   密码调用禁用请求体日志、自动重试和重定向；其余 Inquiry 逻辑不改。

- 无旧密码重设只能供受信任 CM 后端调用。CM 负责校验当前会话、目标用户权限及已审批 Code。
- 调用方认证及接口授权由 internal APIC 负责，与原 BM Client ID 校验的调用方式一致。
- CM 继续使用原 BM DSP.APIC_CLIENT_ID / DSP.APIC_CLIENT_SECRET 向 APIC 发起请求。
  DSP 的两个密码服务不再重复校验这些请求头，不再配置 HTH_CM_APIC_CLIENT_ID / HTH_CM_APIC_CLIENT_SECRET。
  已删除 CmPasswordCallerGuard；不要求网关将 APIC secret 转发给密码服务用于比较。
- DSP 沿用既有公共请求头处理；CM 仍发送 Message-Id 和 Channel=BCO。
  Body 的 clientId 是业务用户所属的 DSP clientId，仍必填，与 APIC 调用方 ID 不同。
- APIC 路由继续复用原 BM DSP.SERVICE_URL，发布上述两个路径到该内部订阅；不得对客户订阅开放。
- DSP application.yaml 对密码接口排除通用请求体审计日志；应用日志只记阶段、结果及异常类型。
  部署配置不得另行打开这两个接口的 HTTP body 调试日志。

HTH 状态保存
在现有 HTH_BEA.HTH_USER_PROFILE 增加四列，使用 HTH 专用 repository 的绑定参数 SQL：
  API_PASSWORD_STATE       NOT_SETUP / ACTIVE / IN_PROGRESS / UNKNOWN
  API_PASSWORD_CLIENT_ID   实际 DSP 业务 clientId，非 APIC client ID
  API_PASSWORD_REQUEST_ID  最近预约操作的 CM requestId
  API_PASSWORD_UPDATED_AT  状态更新时间
不新增表，不恢复 HTH_API_PASSWORD_CREDENTIAL / STATE / OPERATION 三张旧表。
CM 不保存密码或密码 Hash。现有 HTH_USER_PROFILE ORM 不映射这四列，避免旧缓存实体覆盖它们。

流程与一致性
- 新建 HTH profile 默认 NOT_SETUP，生成 SETUP Code；已 ACTIVE 且业务 clientId 相符，生成 RESET Code。
- 新用户在审批前尚未建立 profile，也允许生成 PENDING SETUP Code；审批前不能使用。
  DSP A 仍拒绝覆盖已经存在的密码，用户删除/重建不会绕过该检查。
- 校验正确 Code 后，在同一个本地事务中将状态与 Code 预约为 IN_PROGRESS。
  profile 行锁让同一用户的并发提交只放行一笔；Code 仍使用原有状态和条件更新。
- DSP 返回明确成功后，同一个本地事务更新状态 ACTIVE 并将 Code 标为 USED，再执行成功通知。
- DSP 明确拒绝：Code 恢复 ACTIVE，profile 恢复原设置状态（SETUP 为 NOT_SETUP，RESET 为 ACTIVE）；用户可重新获取公钥再提交。
  HTTP 417 按 errCode 判断：400100/400101/400105、500000 至 500007、600052 是已核对的写入前拒绝。
  其他 417（包括系统错误、缺失或无法解析的 errCode）仍视为结果待确认，不能仅凭 HTTP 417 释放预约。
- 网络超时、5xx、无效响应或 DSP 成功后的本地提交失败：Code 和 profile 均保留 IN_PROGRESS，不再写成 UNKNOWN，
  阻止再写及自动选取 Code 用途，人工与 DSP 核对后恢复；不自动重发，不伪报成功。
- 编辑用户页对 UNKNOWN / IN_PROGRESS 显示状态与待确认提示，不允许生成或查看 Code。
  本次不变更表结构、不自动修复已有 UNKNOWN；历史数据仍需与 DSP 核实后处理。
- 相同已完成 requestId 只返回成功，不再次写 DSP 或通知；当前状态已不确定时拒绝旧成功重放。
- 本地 ACTIVE 仅表示 CM 确认过成功，不能自动感知 DSP 外部停用/删改密码。
  业务 clientId 改变或出现重复 profile 时返回 UNKNOWN，需核对。
