# BCOH2H-1293 — HTH CRM 每日 CSV 抽取技术设计（评审稿）

来源：`[#BCOH2H-1293] MTB DB extract job.pdf`，AC1–AC6。本文是设计，尚未实现或验证作业。关联的 BCOH2H-1394「MTB - Batch job flow」只在 story 中被引用；其具体调度及交接规则尚未取得。

## 1. 目标与边界

每天在可配置时间，从 849 已保存的 `HTH_BEA.HTH_CRM_EVENT_DETAILS` 抽取**前一个香港自然日创建**的 HTH 记录，生成符合已确认接口规格的 CSV，放到下游可取得的目录。支持没有数据、运行记录、失败告警，以及操作员指定抽取日期重跑。

本 story 负责**数据库到 CSV 及本地交接目录**；向 MTB 服务器传送、MTB 接收/入库和文件内容业务解释不在本 AC 中，需与 1394 的批处理流程衔接。849 的 61 字段示例不是已确认的 1293 CSV 字段合同，不能直接据此裁剪或决定字段顺序。

## 2. 现状与改动位置

| 项目 | 当前实现 | 1293 设计 |
|---|---|---|
| HTH 来源 | 849 使用独立 HTH 表；`CREATED_AT` 为落库时的香港本地时间，`EVENT_DTE` 是原业务发生日 | 只读 HTH 表，以 `CREATED_AT` 判定抽取日期 |
| BCO 批处理 | `GenTxnLog2CRM` 读取 `DIGX_CZ_CRM_EVENT3_DETAILS` 的待处理标记，另有活动/匿名用户过滤；输出固定长度 `.dat`，带头尾记录及 `.eof` | **保留原样**。HTH 新增独立 job 和启动脚本，不调用 BCO 的固定长度生成逻辑，不更新 BCO 表 |
| HTH 文件抽取 | 849 尚未实现 | 新增 CSV 查询、映射、写文件、运行记录和重跑流程 |

新作业放在现有 `consulting/middleware/batchJobs` 发布结构中，Java 类和脚本均以 `HthCRM` 命名；UAT/生产各自配置调度参数、数据库连接及目录。可复用现有批处理的**部署/凭据加载方式**，但不直接复用 `GenericOutBoundProcessor` 的文件处理：其现有实现按字段长度处理、把明文列值打印到日志、先创建输出文件且结果保存在内存集合，不适合作为本 story 的 CSV 与敏感数据实现。BCO Java、BCO shell、BCO 表、公共框架和 849 写入链路不改。

## 3. 日期与取数规则（AC1、AC3、AC6）

- 定时运行时，以 `Asia/Hong_Kong` 得到运行日，业务日期 `D = 运行日 - 1 天`。手工重跑必须显式传入 `D`（`yyyy-MM-dd`）；拒绝无效日期和未来日期。
- 单次查询条件：`CREATED_AT >= D 00:00:00` 且 `< (D+1) 00:00:00`。使用绑定参数，不对 `CREATED_AT` 列套 `TRUNC`；按 `CREATED_AT, EVENT_ID` 排序。表本身是 HTH 专用，不加 BCO 的 `BATCH_PROCESSED_DATE`、`EVENT_ACTV_TYPE_CODE` 或匿名用户过滤。不要按 `EVENT_DTE` 过滤：补录或延迟保存可能使业务发生日与创建日不同。
- 同一查询游标的数据库一致性快照确定本次输出集合；逐行读取、逐行写 CSV，记录实际输出行数。`EVENT_ID` 主键保证同一来源记录不会在一次查询中重复；不对业务内容做 `DISTINCT`，避免误删两笔不同事件。若查询/序列化/写盘任一环节失败，整次运行失败，不能发布部分文件。
- 作业仅**读取** CRM 明细，不写处理标记。相同业务日期的重跑重新读取该日期全部符合条件的记录；不会因为前次成功而漏数，也不会夹带其他日期。仅允许同一日期一个运行实例，其他日期仍须遵守批处理资源限制。
- 建议在 HTH 表加 `(CREATED_AT, EVENT_ID)` 索引，先由 UAT 数据量/执行计划验证后落地；索引、运行表 SQL 应单独在 HTH_BEA schema 发布，可重复执行并带 comments，不碰 BCO 表。既有历史行如 `CREATED_AT` 为空，不能按日期可靠归档，应在上线前查明并单独处理，不以 `EVENT_DTE` 猜测替代。

## 4. CSV 与文件发布（AC1、AC2、AC3）

新建显式字段映射（源列 → CSV 列名/位置 → 格式/长度/空值规则），**不使用 `SELECT *` 或把 113 个数据库列自动全部输出**。映射以 MTB 批准的接口规格为准，版本固定并随部署记录。默认按标准 CSV 规则处理分隔符、双引号和换行；字符集、BOM、表头、日期/数字格式、文件名及目录均以正式文件合同为准。密码、Code、hash、token、密钥和原始请求不得进入 CSV 或日志；其他个人资料字段需按字段合同列明是否允许输出。

建议空数据也产出**仅表头 CSV**，运行状态 `SUCCESS`、记录数 `0`，便于下游辨认“作业完成但无数据”。AC2 同时允许“不产文件”；这是待 BA/MTB 确认的业务选择，确认前不把建议当作已批准合同。

文件先写到同一交接文件系统的临时路径，写完并关闭后校验行数、文件大小及文件名，才发布到最终目录。只有最终文件可被下游拾取。若交接约定使用 `.eof`/ready 标记，应在最终 CSV 完整可见后再创建，标记规则由 1394 确认。重跑同一天时先成功生成新文件，再按已确认的版本/替换规则发布；不能先删掉上一份成功文件。若下游已取走该日期文件，操作员需先协调重新接收，避免下游重复入库。

## 5. 运行记录、失败与重跑（AC4–AC6）

新增 HTH 专用运行表，例如 `HTH_BEA.HTH_CRM_EXTRACT_RUN`，不在源明细表增加处理状态。每次运行一行，保存 `RUN_ID`、业务日期、启动方式（定时/手工）、操作员标识（如可得）、开始/结束时间、状态 `RUNNING/SUCCESS/FAILED`、输出记录数、最终文件名、文件大小或校验值（如合同需要）、错误阶段和**脱敏错误码/摘要**。运行时同时写结构化文件日志，便于数据库暂不可用时排查；日志不写 CSV 行内容或数据库凭据。零记录也记成功和 `0`。

作业失败时清理临时文件、保留既有成功文件、把本次记录设为 `FAILED`，脚本返回非零退出码，供现有调度/监控发出人工处理告警。若数据库在启动时已不可用，以本地作业日志和非零退出码补足无法落库的失败记录。AC5 的“alert if possible”先使用已有批处理监控机制；告警通道、收件组和时限需运维确认，不在公共通知链路新增 HTH 特例。

手工重跑只向有批处理操作权限的人员开放，沿用现有作业平台权限，不新增客户界面。命令/调度参数显式指定业务日期；作业记录保留每次尝试及结果。对同一日期加运行锁，防止定时与手工运行互相覆盖。文件重发后的下游去重/替换责任与 1394 对齐。

## 6. 交付物与验证

预期交付：独立 HTH CRM CSV job、独立启动脚本及 UAT/生产配置样例、HTH 运行表/必要索引的可重复执行 SQL、字段映射说明、调度及操作手册。先建 HTH 表/索引与权限，后部署 job，再配置调度；首次上线前先在 UAT 做指定日期回放与文件合同核对。生产切换不重跑历史日期，除非运营指定。

验收至少覆盖：前一日边界（含 00:00:00、23:59:59.999999 和次日 00:00:00）、跨月/跨年、业务发生日与创建日不同、空数据、含逗号/引号/换行的字段、非 ASCII 字符、不同抽取日期各自文件、指定日期重跑、不重复/不漏行、磁盘写入/数据库失败、旧文件保留、并发同日运行拦截、运行表与实际文件行数一致。以真实 HTH 表数据及 MTB 文件合同做 UAT 对账；单元测试只能证明逻辑，不能代替接口验收。

## 7. 评审时必须确认

| 确认项 | 建议/原因 | 确认方 |
|---|---|---|
| CSV 正式字段、顺序、表头、格式、编码、敏感字段处理 | 849 的 61 字段 sample 不能视为 1293 的正式定义；导出必须按 MTB 合同实现 | BA / MTB 接口方 |
| 文件名、目录、ready/`.eof` 及下游拾取方式 | AC 只说“agreed filename pattern”；需与 1394 交接流程一致 | 架构 / 批处理 / MTB 接口方 |
| 无数据是表头文件还是不产文件 | 建议表头文件，但 AC2 留了两个选项 | BA / MTB 接口方 |
| 定时点、工作日/节假日、日界与时区 | 建议每日香港时间、上一自然日；时间和日历应可配置 | BA / 运维 |
| 延迟入库、历史 `CREATED_AT` 空值和补录 | 严格按创建日，错过日期窗口的历史补录须人工指定日期重跑或另立补录机制 | BA / TL |
| 重跑时同名文件替换还是版本化、下游已消费后的处理 | 保证本地旧成功文件不因失败消失；下游重复处理策略需明定 | MTB 接口方 / 运维 |
| 失败告警通道与负责人 | 先靠作业非零退出码接入现有监控 | 运维 / 架构 |

以上文件合同和空数据规则确认后，才能定稿具体 CSV 映射及验收样例；其余 HTH 独立取数、日志和重跑框架可先开发，不影响 BCO。

## 8. 实现记录（2026-10-05）

HTH 独立 Java job、启动脚本、可配置 CSV 栏位与文件名、运行表/索引 SQL、失败状态、同日期并发拦截、指定日期重跑和原子发布已加入仓库。打包为单独 `hth-crm-extract.jar`，不重建 BCO 的 `CDCBatchesUAT.jar`。部署顺序和权限见 `consulting/db/branch_change_history/20261005_BCOH2H-1293/README.md`。

本地 JDBC 替身验证覆盖真实文件输出、日期边界参数、失败保留旧文件、重跑和空数据；尚未连接 UAT Oracle，也未按 MTB 最终文件合同验收。旧 `MTB Interface File Spec.xlsx` 给出了固定长度头尾记录与可选 CSV 明细，而 1293 AC 只写 CSV，因此当前配置中的栏位/文件名属于可执行示例，正式上线前仍需确认第 7 节的接口合同。
